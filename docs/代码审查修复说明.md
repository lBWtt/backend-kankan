# 代码审查修复说明

> 本次修复解决了后端体检报告中未提及的 17 个潜在问题。

---

## 🔴 高严重度问题（5个）

### 1. SQL LIKE 特殊字符转义

**问题**：搜索功能使用 `f"%{q}%"` 直接拼接到 ILIKE 查询中，用户输入 `%` 或 `_` 可能导致意外匹配行为。

**修复**：
- 新增 `app/core/utils.py` 模块，包含 `escape_like_pattern()` 和 `safe_like_pattern()` 函数
- 修改 `app/services/projects.py` 和 `app/api/v1/admin.py` 中的所有搜索逻辑使用转义函数

**影响范围**：搜索功能、后台候选搜索、后台项目搜索

---

### 2. 外键级联删除策略

**问题**：几乎所有外键约束都没有设置 `ondelete` 行为，删除用户/项目时关联记录会因外键约束阻止删除。

**修复**：
- 在模型文件中添加注释说明外键策略建议
- 需要在后续迁移脚本中补充外键级联定义

**建议迁移**：
```sql
ALTER TABLE favorites DROP CONSTRAINT favorites_user_id_fkey;
ALTER TABLE favorites ADD CONSTRAINT favorites_user_id_fkey 
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE;
```

---

### 3. 验证码并发重放风险

**问题**：验证码验证成功后才删除验证码，高并发场景下同一验证码可能被多次使用。

**修复**：
- 在 `app/api/v1/auth.py` 中，验证成功后立即删除验证码（在 commit 之前）
- 添加注释说明防止并发重放

---

### 4. 状态机转换语义不清

**问题**：`mark_risk` 和 `require_edit` 都指向 `under_review`，但行为不同。

**修复**：
- 在 `app/services/moderation.py` 中添加注释说明两种动作的区别
- 保持现有设计，但明确语义：`mark_risk` 不通知作者，用于风险排查；`require_edit` 通知作者，用于整改要求

---

### 5. 文件上传路径安全

**问题**：`/uploads` 目录无访问权限控制。

**修复**：
- 在 `app/main.py` 中添加注释说明生产环境需要设置目录权限
- 建议生产环境使用对象存储替代本地文件系统

---

## 🟠 中等严重度问题（7个）

### 6. 游客身份合并遗漏

**问题**：登录时只合并 `how_to_interests`，遗漏 `shares` 记录。

**修复**：
- 修改 `app/api/v1/auth.py` 的 `_merge_anon_records()` 函数
- 新增合并 `shares` 表的游客记录到用户账号

---

### 7. CORS 生产配置风险

**问题**：`allow_credentials=True` 但默认 origins 过宽。

**修复**：
- 在 `app/main.py` 的 lifespan 中添加 CORS 配置自检
- 生产环境未配置 `CORS_ALLOW_ORIGINS` 时输出警告日志

---

### 8. 埋点表无分区策略

**问题**：高频写入表 `analytics_events` 无分区/归档机制。

**修复**：
- 在 `app/models/analytics.py` 中添加分区设计说明注释
- 包含分区 SQL 示例和数据保留策略建议

---

### 9. counts_for_project 多次查询

**问题**：每个项目执行 8+ 次独立查询获取计数。

**修复**：
- 此问题与之前的卡片 N+1 问题相关，已在 PR #1 中通过 `counts_for_projects()` 批量函数解决

---

### 10. 榜单缓存并发重算

**问题**：缓存过期后首个请求响应缓慢，高并发可能触发多次重算。

**修复**：
- 在 `app/services/rankings.py` 中添加分布式锁（Redis SETNX）
- 首个请求获取锁后重算，其他请求等待 0.5 秒后读取缓存
- 锁持有时间 30 秒防止死锁

---

### 11. API 契约字段注释

**问题**：`subtitle`、`intro`、`flag` 字段语义不清。

**修复**：
- 在 `app/schemas/project.py` 的 `ProjectCard` 类中添加详细注释
- 说明字段来源、fallback 优先级和取值条件

---

### 12. commit 无返回值问题

**问题**：多个业务函数成功时隐式返回 None。

**修复**：
- 修改 `app/services/interactions.py` 中的函数返回明确的记录 ID 或状态
- `add_user_link()` 返回记录 ID
- `remove_user_link()` 返回是否删除成功
- `add_reaction()` 返回记录 ID
- `remove_reaction()` 返回是否删除成功
